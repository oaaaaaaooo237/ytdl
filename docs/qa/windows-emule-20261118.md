# CaptainFlash Windows 1.2.0 RC1 电驴验证

- 用上游发布的 SHA-256 校验 aMule 3.2.0 Windows x64 便携包和源码归档。便携包包含本机引擎、控制 API、第三方声明和对应源码。控制 API 仅绑定回环地址。
- 用独立配置实际启动、认证、关闭和重启引擎。用 eD2k 全局与 Kad 各搜索一次，均有真实结果。应用界面一次全局搜索收到 166 条结果。通过 Qt 测试驱动打开搜索、切换两个页签、点中结果、确认下载、查看队列、暂停、取消并正常关闭窗口。
- 公共 P2P 实测下载到字节数据，暂停后关闭并重启引擎，核对已下载的 1,589,874 字节仍在队列。使用已联网的引擎下载官方开源测试文件 `eMule0.72a-Sources.zip`，完成 4,345,733 字节，SHA-256 与上游一致。测试期间未运行下载文件。
- 两次新建配置从应用地址框直贴上述文件链接均已入队。观察窗口内未完成，未将这两次计为应用历史端到端通过。历史记录的路径、文件大小、去重与记录删除行为由测试覆盖。
- 搜索页面使用现有主题，以离屏渲染检查页签、结果列表、字号和布局。便携程序在独立配置中检查启动，窗口自动化在 Qt 离屏环境运行。
- Windows 候选包供试用。待复验项目为另一台 Windows 电脑的安装包启动，以及冷启动从链接到历史的完整链路。

上游测试文件见 [eMule 0.72a 发布页](https://github.com/irwir/eMule/releases/tag/eMule_v0.72a-community)。

## RC2 交付包实测

- 解压 RC1 交付 ZIP，利用 Agent Desktop 从首页输入 `Debian ISO` 并点击电驴按钮，复现「无法初始化本机电驴引擎」。诊断构建定位到本机 HTTP 客户端创建通用 opener 时提前初始化 HTTPS。在 Windows 打包环境中，HTTPS 初始化抛出文件找不到异常，应用立即关闭已启动的引擎。
- RC2 只为回环地址创建 HTTP 处理器，等待所选网络连接成功后再提交首次搜索。首页使用侧脸驴头并标注「电驴」。Windows 启动清单指定以当前用户权限运行。
- 解压最终 RC2 ZIP，使用全新的配置。以普通账户权限在后台操作，首页首次搜索 `Debian ISO` 返回 492 条真实结果。整个过程无需授权或配置防火墙。测试窗口与引擎按顺序退出。
- 使用另一个全新配置从首页粘贴官方 eD2k 链接，确认后入队。界面实际走过「等待来源」→「已暂停」→「等待来源」。测试时文件没有可用来源，观察止于队列。退出后确认 CaptainFlash 和两个引擎进程均已结束。

## 2026-11-19 冷启动直链落盘复验

- 使用同一交付 ZIP（SHA-256 `A879894408C890CA937F98F9E1776CA13D097A3C7C53879B6B3D9A67EAD7FA9F`），解压到新目录并使用隔离配置。点击下载前确认 Windows 上的电驴引擎尚未启动。
- 用 Agent Desktop 在后台将含测试来源地址的 eD2k 链接填入首页并确认下载。一份 80,000 字节自建文本由 WSL 中的独立 aMule 节点供应，Windows 普通用户权限下运行原交付程序。仅测试配置允许私网来源。
- 核对程序历史界面实际显示文件名、eD2k 和「已完成」。历史记录里的路径指向已落盘文件，成品 SHA-256 与提供端原文件一致。测试后关闭窗口、Windows 引擎及 WSL 测试来源。
