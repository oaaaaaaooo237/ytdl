# Windows v1.0.1 单文件格式兼容修复

日期：2026-09-22

## 问题与证据

- 本轮 GitHub `gh release list` 确认最新正式 Windows 发布为 `win-v1.0.0`（2026-06-19）；本地新增 v1.0.1 修复包，尚未发布 GitHub。
- v1.0.0 安装包内置 yt-dlp 2026.03.17；当前用户配置实际选择 2026.08.19。两者都能解析用户提供的地址，因此本次复现并非解析器版本过旧。
- 真实元数据返回 8 个 MP4 格式，分辨率为 240p、360p、480p、720p，各有普通与 AV1 候选。普通格式未提供 vcodec/acodec，AV1 仅提供 vcodec。
- PC 原筛选条件要求两个编码字段都存在且不为 none，导致所有格式被过滤，进入“分析完成，但没有可直接下载的格式”。Android 将缺失编码视为未知，只有明确 none 才表示无对应轨道。
- Android 另有 Eporner 元数据 HTTP→HTTPS 规则，但本轮 PC 网络分析成功，未将这处差异认定为本次根因，也未扩展网络层。

## 最小修复范围

- 同步缺失编码不等于缺失轨道的识别规则；对于编码不完整的单文件，仅在存在正分辨率、视频容器和 HTTP(S) 媒体地址时接受。
- 界面注明“单文件”及未知编码，不伪造 H.264/AAC，不把单文件声称为独立音频或无音轨视频。
- 沿用 PC 的音频+视频单文件下载路径；保留精确 format_id 和分辨率选择。未移植 Android 页面、原生网络栈或播放器。
- 本地版本提升至 Windows v1.0.1。

5. PyInstaller 构建成功；打包 smoke 确认 yt-dlp 2026.03.17、ffmpeg 8.1 可运行。
6. 打包 EXE 在隔离 APPDATA、禁用启动更新的 offscreen 环境启动，Qt 事件循环持续运行，无 traceback。
7. `format-smoke.png` 是 Qt 离屏渲染的脱敏技术截图，已检查文字布局；不是前台操作截图。
