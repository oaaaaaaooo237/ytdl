# Android 1.0.1 任务标题与下载进度精简设计

## 目标

进一步压缩任务卡片中的无效信息：下载过程和历史记录不再显示输出文件名；单行媒体标题过长时自动从右向左循环；下载进度只用图标和数值表达，不再显示“速度、已下载、总计”等说明文字。

本次只调整任务卡片的展示，不改变下载流程、文件命名、历史数据、打开、分享、再次下载或删除行为。

## 采用方案

采用 Jetpack Compose 自带的单行跑马灯，并继续使用项目已有的自绘 `ImageVector` 风格绘制下载和硬盘图标。

- 当前任务、等待任务和历史任务的标题都保持单行。
- 标题宽度足够时静止；发生溢出时从右向左循环滚动。
- 不自写计时器或位移动画，避免额外状态和生命周期处理。
- 不使用字符“↓”或表情符号作为图标，也不引入 Material Icons Extended 等新依赖。

没有采用以下方案：

1. 自写无限位移动画。它可以精确控制轨迹，但需要维护位移、文本宽度和动画重启状态，超出本次需求。
2. 定时切换标题片段。它会造成文字跳动，阅读体验不如连续滚动。

## 标题与文件名

- 当前下载卡片继续使用分析得到的媒体标题，不显示进度回调中的临时文件名。
- 历史卡片第二行删除输出文件名，仅保留有意义的媒体类型、完成时间和经过安全处理的失败原因。
- 输出 URI 和真实文件名继续保存在内部，用于打开、分享和删除，不因前台隐藏而修改。
- 标题跑马灯只作用于可见标题，不改变标题内容或数据库值。历史搜索继续匹配标题和仍然可见的第二行信息，不再匹配已经隐藏的文件名。

## 下载进度

进度条下方改成同一行的两组信息：

`[下载图标] 3.2 MB/s    [硬盘图标] 126.4 MB/512.0 MB`

- 下载图标采用“向下箭头落入横线”的实心矢量图形。
- 容量图标采用同样线条粗细和视口尺寸的硬盘矢量图形。
- 图标与文字使用相同的弱化前景色，尺寸略小于正文，不抢占标题和状态徽标的视觉层级。
- 速度、已下载容量和总容量的数字均固定显示一位小数。
- 每个容量值使用适合自身数值的 `B`、`KB`、`MB` 或 `GB` 单位；已下载和总容量之间只用 `/` 分隔。
- 下载容量缺失时按 `0.0 B` 显示；速度未知时显示 `--`；总容量未知时显示 `--`，不制造估算值。
- 总容量继续沿用现有规则：同一下载阶段第一次得到有效值后保持不变，进入下一下载阶段后允许使用新阶段的总容量。
- 可访问性语义仍提供中文说明，屏幕阅读器可以读出“下载速度、已下载、总容量”；这些说明不显示在界面上。

## 改动边界

- 不改数据库结构和历史实体。
- 不改下载回调、排队、取消、重试、导出或文件命名逻辑。
- 不改右侧状态、编码和分辨率徽标。
- 不改下载页和任务页滚动条。
- 不重构与任务卡片无关的格式化函数；为进度数值使用独立的一位小数格式化规则，避免改变设置页缓存大小等既有文案。

## 验收标准

1. 单元测试证明进度文本不含“速度、已下载、总计、未知”，速度和容量数字固定一位小数。
2. 单元测试覆盖 `B`、`KB`、`MB`、`GB`、未知速度和未知总容量。
3. Compose 测试证明当前任务的进度区包含下载图标和硬盘图标。
4. Compose 测试证明当前任务、等待任务和历史任务标题均使用单行从右向左循环的标题组件。
5. 历史映射测试证明第二行不再包含输出文件名，但媒体类型、时间和安全失败原因仍保留。
6. 回归测试证明下载卡片不显示进度回调中的临时文件名。
7. API 37 前台可见模拟器验证：长标题自动从右向左循环，进度行图标清晰、数字不重叠，历史任务不显示文件名。
