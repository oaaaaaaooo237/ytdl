# Android 未知元数据单文件格式设计

日期：2026-07-17

## 背景

部分采用通用网页播放器的网站只向 `yt-dlp` 暴露一个可直接下载的媒体地址。此类结果具有明确的 `format_id` 和视频容器扩展名，但可能没有分辨率、宽度、视频编码、音频编码和文件大小。当前 Android 映射层要求视频格式必须包含 `height` 才算可用，因此分析虽然成功，界面仍显示没有可选格式。

## 目标

- 允许这类信息不完整的单文件视频作为“原始格式”下载。
- 不伪造分辨率、编码、文件大小或音视频流信息。
- 未知元数据格式只走单文件直接下载，不进入视频和音频分离、原生合并或纯音频下载。
- 保持所有已知分辨率格式的选择、排序、编码切换和下载路线不变。
- 作为 `1.0.3` 独立分支开发，保留现有 `1.0.2` 分支和发布包不变。

## 识别规则

只有同时满足以下条件的格式才按未知元数据单文件视频处理：

1. `format_id` 非空；
2. `height` 为空；
3. `vcodec` 和 `acodec` 都没有明确值，而不是显式的 `none`；
4. 扩展名属于常见视频容器，例如 `mp4`、`m4v`、`mov`、`webm`、`mkv` 或 `3gp`。

显式标记为纯音频、视频编码缺失但容器属于音频类型、格式 ID 为空的条目继续保持不可用。

## 界面和选择行为

- 只有未知元数据格式时，视频模式显示一行“原始格式”，摘要显示容器和“单文件”，默认选中。
- 同时存在已知分辨率和未知元数据格式时，已知格式继续参与“自动（推荐）”和分辨率排序；未知格式单独显示为“原始格式”，不参与分辨率比较。
- “视频+音频”模式不使用未知元数据格式；没有明确独立音频流时，纯音频模式保持不可用。
- 不显示 `nullp`、虚构分辨率或内部格式 ID。

## 下载行为

选择“原始格式”后，下载请求使用分析结果中的明确 `format_id`，生成 `DownloadRoute.DirectSingleFile`。下载器不改写格式选择，不启动原生合并，也不推断音频或视频编码。

## 验证

- 映射测试：未知元数据 MP4 被标记为可用并显示“原始格式”；明确纯音频和非视频容器仍不可用。
- 选择测试：只有未知格式时默认选中“原始格式”；已知与未知共存时不出现 `nullp`，自动推荐仍选择已知格式。
- 路由测试：未知格式只能生成 `DirectSingleFile`，不能生成合并或纯音频路线。
- 回归测试：格式映射、格式选择、下载路由、全量 Android 单元测试和 debug 构建通过。
- 真实地址只做分析和必要的受控单文件验证；锁屏期间的后台或仪器测试不计为前台可见验收，解锁后再补界面确认。

## 非目标

- 不为特定网站新增专用解析器。
- 不修改 Android 原生网络回退策略。
- 不探测或猜测真实分辨率。
- 不把未知格式拆成视频流和音频流。
- 本轮不发布 Google Play 包。
