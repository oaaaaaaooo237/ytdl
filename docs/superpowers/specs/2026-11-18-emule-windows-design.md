# Windows 电驴搜索与下载设计

## 范围

先交付 Windows 本机版，再开发 Android 本机版。两个版本均在运行应用的设备上连接 eD2k/Kad 网络、接收文件并保存到该设备。Windows 首版以 aMule 3.2.0 的 `amuled` 与 `amuleapi` 为候选引擎。Android 后续单独验证 ARM64 原生引擎、前台服务、存储与进程恢复，再制定实现计划。

## 交互

- 下载页地址框右侧增加驴头图标，提示文字为「电驴搜索」。输入非空关键词后点击，打开应用内搜索页并执行搜索。网页地址和现有下载流程继续使用原入口。粘贴有效的 `ed2k://|file|` 链接时，在下载页直接加入电驴队列。
- 搜索页顶部有搜索框和网络选择，可在此继续搜索。每次搜索开一个可关闭的页签，标签显示关键词开头及命中数，完整关键词放在提示文字中。切换页签保留各自的结果和选中项。失效页签保留已显示的结果，并提供重新搜索入口。
- 列表显示文件名、大小、完整来源和总来源，优先展示完整来源多的结果。点击结果弹出详情和「下载」按钮，确认后按文件哈希加入队列并反馈状态。搜索中、无结果、网络未连接和引擎不可用分别显示明确反馈。
- 电驴任务出现在现有队列，显示等待来源、下载速度、进度、暂停、校验、完成或出错。提供暂停、继续、取消。关闭再打开应用后根据引擎保存的状态恢复。完成并确认文件存在后写入下载历史。
- 设置提供「电驴」分组，包含连接状态、默认搜索网络、上传与下载限速、完成文件目录。网络选择提供 eD2k 全局、Kad 和全部。图标、字号、按钮、行间距、主题和弹窗沿用现有 Windows 界面。

## 引擎与文件

- 应用在首次使用电驴功能时启动本机独立配置的引擎和 API，启动、搜索与轮询放在后台任务。控制 API 仅绑定本机回环地址，使用应用生成的凭据，凭据不进入日志。首版打包验证采用官方便携二进制，并核对对应源码、许可证与第三方声明的交付方式。
- 引擎管理 P2P 连接、文件校验、临时文件和断点。应用按搜索 ID 查询结果，按哈希识别队列项和合并同一文件，状态更新回到 GUI 线程。通过引擎上报的完成状态和实际输出文件来确认完成。
- 引擎使用独立临时与完成目录，普通下载目录和用户其他目录不加入电驴共享范围。界面说明 P2P 下载可能向同网用户上传文件片段。取消时要求确认，已完成文件使用现有历史管理入口。
- 先用隔离的引擎配置验证 Windows 便携包、本机 API、eD2k/Kad 搜索与可控来源下载，再接入界面。无可用来源时显示等待状态，搜索命中与实际可下载分开验证。

## 验收

1. 用有权分发的文件验证中文及英文关键词、连续搜索、页签回切、点击结果、确认下载和直接粘贴 eD2k 文件链接。
2. 验证真实字节进度、暂停、应用重启、继续、取消及最终文件校验。完成后从历史打开对应本机文件。
3. 验证网络断开、未就绪、搜索无结果和无来源时界面仍可操作。回归普通链接分析、队列与历史流程。
4. 在未安装 aMule 的 Windows 测试环境验证成品包从解压启动到搜索和下载。引擎随包提供，经本机完成 P2P 下载。通过后再启动 Android 引擎验证。

资料见 [aMule 3.2.0](https://github.com/amule-org/amule/releases/tag/3.2.0) 和 [3.2.0 API 契约](https://github.com/amule-org/amule/blob/3.2.0/docs/api/REFERENCE.md)。
