# Android 1.0.4 断点续传与断网恢复设计

## 目标

在保持单任务顺序下载、现有 yt-dlp 解析能力和 Android 原生合成方式不变的前提下，为下载任务增加：

- 网络断开后进入“等待网络”，不直接记为失败；
- 网络恢复后自动尝试从已有进度继续；
- 用户可以手动暂停和继续当前任务；
- 应用进程结束或手机重启后，重新打开应用仍能找回任务并继续；
- 明确区分暂停、等待网络、取消和失败，避免用户误以为进度已经丢失。

断点续传是一项尽力而为的能力。服务器支持字节范围或分片续传时保留已有进度；服务器拒绝续传、临时地址失效或格式发生变化时，只重新下载当前未完成的流，不重复下载已经完成并通过校验的其他流。

## 不在本次范围内

- 不增加同时下载数量，仍然固定并发为 1；
- 不实现多连接分片加速；
- 不接管 yt-dlp 的站点解析、鉴权和 DRM 判断；
- 不在开机后自行弹出界面或强制启动前台服务；
- 不承诺直播流、一次性流或拒绝范围请求的网站一定能够原位置续传；
- 不改变解析器版本管理、输出文件命名、用户下载目录和媒体合成规则。

## 方案比较

### 方案一：只保留本次运行中的 `.part`

沿用现有 yt-dlp 的 `continuedl = true` 和 `.part` 文件，只在网络失败时延长重试时间。

优点是改动最小；缺点是任务和目录仍由内存管理，进程结束后无法恢复，也无法可靠区分手动暂停与取消。不满足本次范围。

### 方案二：持久化任务和稳定工作目录

继续由 yt-dlp 下载，由 Android 服务负责网络状态、任务状态和持久化；每个任务拥有稳定的 App 私有工作目录和加密请求记录。暂停或断网时退出当前下载调用，但保留工作目录，继续时重新分析地址并让 yt-dlp 使用同一输出模板续传。

该方案复用现有下载器对普通文件、HLS 和 DASH 的处理，同时能覆盖应用重启恢复，改动集中在任务状态、服务、持久化和清理边界。采用该方案。

### 方案三：Android 原生分段下载器

由 Android 自行发送范围请求并管理每个分片。

它对普通文件控制更直接，但会重复实现 yt-dlp 已有的重试、分片、请求头和站点适配能力，而且难以统一处理 HLS、DASH、临时地址及特殊请求。不采用。

## 用户可见行为

### 网络断开

1. 下载器遇到连接中断后，先由 Android 判断当前是否存在经过系统验证的网络。
2. 没有可用网络时，任务进入“等待网络”，速度显示为 0，进度和已下载大小保留。
3. 当前任务继续占据队首，后面的任务保持等待，严格维持原有顺序。
4. 网络恢复并稳定后，服务自动尝试继续，不要求用户重新点击下载。
5. 系统仍有可用网络、但网站返回拒绝访问、格式失效或其他站点错误时，不得无限显示“等待网络”。这类问题按有限重试或普通失败处理。

### 手动暂停和继续

- 下载中的任务显示“暂停”和“取消”。
- 点击“暂停”后先显示“正在暂停”，当前下载调用退出并完成状态落盘后显示“已暂停”。
- 暂停期间已下载文件不得继续增长；任务进入“已暂停”后释放唯一下载名额，下一条等待任务自动开始。
- 点击“继续”后显示“正在继续”。如果没有其他任务正在下载，立即重新分析地址并尝试续传；如果已有任务正在下载，则把该暂停任务放到等待队列最前面，但不打断当前任务。
- 点击“取消”仍表示放弃任务：删除该任务未导出的临时文件，写入取消历史，并允许下一条任务开始。

### 应用或手机重启

- 正在下载、正在暂停或等待网络的任务必须先写入持久化记录，再更新前台状态。
- 应用进程结束或手机重启后，不自动从后台启动下载。
- 用户再次打开应用时，在后台读取未完成任务；原“下载中”或“等待网络”状态恢复为“已暂停”，并显示“应用曾退出，点击继续”。
- 用户点击“继续”后再启动前台服务。如果此时没有网络，任务转为“等待网络”；有网络则立即尝试续传。
- 尚未开始的等待任务也恢复，并保持原来的加入顺序。

### 不支持续传的网站

- 如果服务器接受范围请求或 yt-dlp 能识别已有分片，继续已有进度。
- 如果服务器忽略范围请求并重新发送完整文件，允许 yt-dlp 重新下载当前流，同时显示一次“该网站无法接着下载，已重新下载当前文件”。
- 如果临时媒体地址过期，先用原页面地址重新分析，再使用原格式 ID 获取最新地址。
- 原格式 ID 已不存在时不得静默切换清晰度或编码。任务保留为可重新选择状态，提示用户重新分析和选择格式。
- 直播流或无法确认内容一致性的文件不得拼接旧数据；当前流从头开始，其他已经完成并校验通过的流仍保留。

## 状态模型

在 `DownloadStage` 中增加：

- `Pausing`：已收到暂停请求，等待当前下载调用安全退出；
- `Paused`：工作目录和检查点已保存，没有网络活动；
- `WaitingForNetwork`：系统没有经过验证的可用网络；
- `Resuming`：正在重新分析并准备继续。

状态转换遵循：

```text
Waiting -> Downloading
Downloading -> Pausing -> Paused -> Resuming -> Downloading
Downloading -> WaitingForNetwork -> Resuming -> Downloading
Downloading/Paused/WaitingForNetwork -> Canceled
Downloading/Resuming -> Failed
Downloading -> Merging -> Exporting -> Completed
```

`Paused` 和 `WaitingForNetwork` 都不是终态，也不写入历史记录。`Paused` 释放下载名额，允许下一条等待任务开始；`WaitingForNetwork` 仍占据当前顺序，网络恢复前不启动后续任务。只有 `Completed`、`Failed` 和 `Canceled` 写入历史。

## 网络判断和重试

- 使用 `ConnectivityManager` 的默认网络回调，只有具备 `NET_CAPABILITY_INTERNET` 和 `NET_CAPABILITY_VALIDATED` 的网络才视为可用。
- 网络恢复后等待一个短暂稳定窗口再继续，避免 Wi-Fi 和移动网络切换时反复启动。
- 下载器报网络错误但系统仍有有效网络时，最多进行有限次数退避重试；达到上限后按失败处理。
- HTTP 403、404、410、格式不存在和网站拒绝访问不能仅凭错误文字归入“断网等待”。
- 网络反复断开时不累计为普通失败；任务持续停留在“等待网络”，直到用户取消、网络恢复或应用退出。
- yt-dlp 请求使用有上限的连接和读取超时，手动暂停即使遇到失去响应的连接，也必须在超时后退出“正在暂停”。
- 网络回调、退避等待和任务执行器都不得进行无限期阻塞等待；每次等待设置超时并重新检查取消、暂停和网络状态。
- 下载停止原因必须使用明确类型区分“用户暂停”“等待网络”“用户取消”和“服务生命周期结束”。服务被系统销毁或应用进程结束不得按用户取消处理，也不得删除断点文件。
- 暂停只有在下载工作线程已经停止、文件句柄已经关闭且检查点落盘后才算完成；超过规定时间仍未停止时保留工作目录并报告安全错误，不得启动第二个下载线程或删除文件。

## 续传工作目录和检查点

### 稳定目录

- 每个任务创建不可由 URL 或标题推导的随机任务 ID。
- 工作目录固定为 App 私有目录下的 `task-<id>`，继续下载时复用同一目录。
- 路径必须经过规范化和父目录校验，不接受数据库或加密记录提供的任意文件路径。
- 用户下载目录只接收完成并校验后的成品，不保存 `.part`、检查点或请求记录。

### 原子检查点

每次阶段变化和有效进度更新后，保存最少必要信息：

- 当前阶段；
- 视频、音频和字幕各自是否已经完成；
- 已完成文件的相对路径、大小和格式 ID；
- 当前流已下载大小、总大小和最后更新时间；
- 是否因为断网、手动暂停或应用退出而停止。

检查点先写 `.tmp`，同步到磁盘后原子重命名。恢复时只信任 App 私有目录中的相对路径，并重新核对文件存在、大小大于 0、格式 ID 与请求一致。

### 分阶段恢复

- 单文件任务：继续同一 `.part`；不支持范围请求时只重下该文件。
- 视频+音频任务：视频已完成后断在音频阶段，恢复时跳过视频，只继续音频。
- 合成阶段中断：保留已完成的视频和音频，删除不完整合成文件，重新执行合成。
- 导出阶段中断：App 私有成品保持不变，重新执行导出；不得重新下载或重新合成。
- 字幕失败仍沿用现有独立失败规则，不把字幕问题误判为网络等待。

## 持久化结构

### Room 安全摘要

复用现有 `queue_items` 表保存可直接用于列表显示的安全字段，并通过数据库迁移增加：

- 稳定任务 ID 和队列顺序；
- 当前阶段和暂停原因；
- 已下载大小、总大小及进度；
- 检查点更新时间。

Room 中不得保存完整 URL、cookies 内容、请求头、临时媒体地址或原始异常。

### 加密恢复请求

新增独立的恢复请求存储，使用 Android Keystore AES-GCM 加密，并采用 `.tmp` 后原子重命名。内容只包括恢复所必需的数据：原页面地址、标题、精确格式 ID、下载模式、字幕选择和安全的任务标识。

恢复请求不保存 cookies 内容，也不保存 yt-dlp 提取出的临时媒体地址。需要 cookies 时，每次继续前从设置中现有的用户文件引用重新生成任务临时副本；暂停或等待网络完成后删除该副本。文件引用失效时进入“需要重新选择 cookies 文件”，不得泄露引用或内容。
恢复请求还要记录原任务是否使用了 cookies，但不保存 cookies 内容或文件引用；只有原任务使用过 cookies 时，继续下载才从设置中的现有引用创建临时副本。

### 启动恢复

- 应用启动读取 Room 安全摘要，并在后台校验对应加密请求和工作目录。
- 三者缺一、解密失败或路径校验失败时，不自动下载；显示安全错误并允许删除任务。
- 恢复过程不能阻塞首屏，也不能发起网络请求，只有用户点击“继续”后才重新分析。

## 下载器接入

- 保留 Python 侧 `continuedl = true` 和 `nopart = false`。
- 同一任务每次继续都使用同一工作目录和确定性输出模板。
- 继续前重新分析原页面，核对原格式 ID；不保存或复用过期的直链。
- Android 只管理任务生命周期、网络状态和检查点，不复制实现 yt-dlp 的站点请求逻辑。
- 进度回调发现已下载大小明显回到起点时，视为当前网站拒绝续传，更新提示但不泄露地址或响应内容。

## 文件清理规则

| 情况 | 临时下载文件 | 加密恢复请求 | Room 队列记录 |
| --- | --- | --- | --- |
| 手动暂停 | 保留 | 保留 | 保留 |
| 等待网络 | 保留 | 保留 | 保留 |
| 应用退出 | 保留 | 保留 | 保留 |
| 用户取消 | 删除 | 删除 | 移出活动队列并写取消历史 |
| 普通不可恢复失败 | 删除未完成文件 | 转为现有失败重试草稿 | 移出活动队列并写失败历史 |
| 完成并导出 | 按现有规则清理中间文件 | 删除 | 移出活动队列并写完成历史 |

现有“清除缓存”不得删除活动、暂停或等待网络任务的工作目录，不得删除解析器版本或用户成品。删除暂停任务只能通过该任务的“取消/删除”操作完成。

### 删除安全边界

- 所有删除入口只接收经过格式校验的稳定任务 ID，不接收数据库、检查点、下载结果、异常信息或界面参数携带的任意文件路径。
- 删除目标必须由程序使用固定的 App 私有任务根目录和任务 ID 重新计算为 `task-<id>`。任务 ID 必须完整匹配 `^[0-9a-f]{32}$`；包含路径分隔符、`..`、盘符、绝对路径、编码后的路径字符或其他内容时一律拒绝。
- 规范化后的目标必须是任务根目录的直接子目录，名称必须与任务 ID 完全一致；目标不得等于任务根目录本身，也不得落入父目录、相邻任务目录或其他 App 私有目录。
- 任务工作目录本身是符号链接或 Windows/Android 等价的重解析入口时拒绝清理。目录内部采用不跟随符号链接的遍历方式：遇到链接时只删除链接项本身，不得访问或删除其指向目标；无法可靠判断时整次清理失败并保留文件。
- 执行前必须确认目标任务不属于其他正在下载、正在继续或正在导出的任务。用户取消只能清理同一任务的工作目录，不能使用当前活动任务的路径替代待取消任务。
- 任务清理范围不得包含解析器版本、cookies 来源文件、临时 cookies 根目录、用户下载目录、SAF 导出的成品、另一个任务目录或 App 私有根目录。临时 cookies 仍由现有专用组件按其受控引用独立清理。
- 删除操作必须可重复执行：目标已经不存在时视为清理完成；删除中途失败时记录“待清理”并停止，不得改删父目录、扩大范围或通过模糊匹配寻找相似目录。
- 取消任务、删除历史或清除缓存都不得删除已经导出的用户成品。本次不增加“同时删除成品”的功能。

## 前台界面和通知

- 下载卡片右侧状态使用“下载中 / 正在暂停 / 已暂停 / 等待网络 / 正在继续”。
- 暂停和等待网络时保留进度条、已下载大小和总大小；速度显示为 0，不显示虚假 ETA。
- 下载中显示“暂停 / 取消”；已暂停显示“继续 / 取消”；等待网络显示“取消”，网络恢复后自动继续。
- 通知与应用内状态一致，提供暂停、继续和取消动作；恢复失败只显示安全中文摘要。
- 用户可见文案不出现 `web`、`媒体文件`、内部格式角色、完整 URL、IP、cookies、请求头或原始异常。

## 队列规则

- 固定并发 1，持久化后的队列仍按原加入顺序执行。
- `Pausing` 期间仍占据下载名额；确认进入 `Paused` 后释放名额，下一条等待任务自动开始。
- 已暂停任务点击“继续”时，如果已有任务正在下载，则插入等待队列最前面；当前任务完成后优先继续它，但不得中断当前下载。
- `WaitingForNetwork` 仍占据原队首，系统网络恢复前后续任务全部等待，避免断网时整队反复失败。
- 当前任务完成、普通失败或取消后，下一条任务开始。
- 应用恢复时先恢复原当前任务，再恢复后续等待任务；不得因为更新时间变化打乱顺序。

## 测试设计

### 单元测试

- 状态机覆盖暂停、断网、恢复、取消、失败和完成的合法转换；
- 网络可用性与 HTTP/站点错误分类分离；
- 稳定任务目录、相对路径校验和越界拒绝；
- 删除接口拒绝 `..`、分隔符、绝对路径、编码路径、畸形任务 ID、任务 ID 与目录不一致以及根目录本身；
- 删除一个任务后，相邻任务目录、任务根目录哨兵、解析器版本、cookies 来源和用户成品必须保持不变；
- 符号链接测试确认清理不会跟随链接删除目标；无法判断链接类型时保留文件并报告待清理；
- 删除与下载、继续、导出并发时必须拒绝错误任务，取消同一任务要先停止并关闭文件；重复删除两次结果一致；
- 检查点原子写入、损坏恢复和阶段跳过；
- Room 3 到 4 迁移保留现有历史和队列数据；
- 加密恢复请求不包含明文 URL、cookies、请求头或临时直链；
- 暂停和断网不清理 `.part`，取消和不可恢复失败按规则清理；
- 手动暂停释放名额，继续任务回到等待队首且不打断当前任务；等待网络仍阻塞整队；应用恢复不改变保存的顺序。

### Python 测试

- 下载参数继续保持 `continuedl = true`、`nopart = false` 和确定性输出模板；
- 连接和读取超时、重试次数均为有界配置，暂停测试覆盖无进度连接在超时后退出；
- 同一目录再次调用时复用 `.part`；
- 进度回调只传安全的数值状态，不向 UI 传完整文件路径或异常。

### Android 仪器测试

使用本地受控 HTTP 服务分别模拟：

- 支持 `Range`：中断后返回 206，最终文件与源文件哈希一致；
- 不支持 `Range`：恢复后重新下载当前流，最终文件正确且提示明确；
- 网络断开和恢复：任务停在“等待网络”，恢复后自动继续；
- 暂停和恢复：暂停期间文件大小稳定，继续后完成；
- 服务和状态仓库重建：任务仍可恢复，已完成的视频阶段不重复执行。

### 前台可见模拟器验收

1. API 37 可见模拟器开始一个足够大的真实下载，确认进度和速度实际变化。
2. 关闭模拟器网络，确认卡片变为“等待网络”而不是失败，并保留进度。
3. 恢复网络，确认任务自动继续；支持续传的来源不得从 0 开始。
4. 手动暂停，等待至少 10 秒确认已下载大小不变，再点击继续。
5. 暂停后结束应用进程并重新打开，确认任务仍在，点击继续后完成。
6. 视频+音频任务在视频完成、音频下载中断后继续，确认视频阶段没有重复下载，最终原生合成成功。
7. 取消任务，确认活动任务消失、历史显示取消、App 私有目录没有该任务的 `.part`。
8. 取消前在相邻任务目录和任务根目录放置测试哨兵，确认只删除被取消任务的私有工作目录，其他任务、解析器版本和用户成品不变。
9. 所有真实地址只在前台验收过程中使用，不把成人内容、完整地址或标题写入提交的测试证据。

## 发布标准

- 版本号更新为 1.0.4，版本代码递增；
- Python 测试、Android 聚焦单测、`testDebugUnitTest`、`assembleDebug` 和必要仪器测试依次通过；
- Gradle 固定使用项目规定的 9.4.1，并加 `--no-parallel`，各任务顺序执行；
- 完成代码审计，清除本次产生的冗余状态、重复重试逻辑、临时探针、无用导入和无意义注释；
- 在前台可见模拟器完成断网、恢复、手动暂停、应用重启、单文件和视频+音频验收后，才允许发布 1.0.4；
- 发布记录明确列出不支持范围请求、临时地址变化和直播流等剩余限制。
