# Android 1.0.1 任务页动态滚动条设计

## 目标

- 任务页内容超过一屏时，在右侧显示与列表当前位置同步的滚动条。
- 任务页内容不足一屏时不显示滚动条。
- 下载页内容超过一屏时继续支持手指上下拖动，不增加常驻滚动条。
- 保持当前页面结构、配色和底部导航不变。

## 当前情况

- 下载页、任务页和设置页共用一个 `LazyColumn`，因此下载页和任务页已经支持上下拖动。
- 当前任务页右侧的 `QueueScrollIndicator` 是固定装饰：它只根据“存在当前任务或等待任务”决定是否显示，不能判断列表是否真的超过一屏，也不会随滚动位置变化。
- 只有历史任务很多、但没有当前或等待任务时，现有装饰条不会显示。

## 交互设计

1. 当前页面在自己的页面范围内创建 `LazyListState`，切换页面后不会沿用另一页的滚动位置。
2. 仅任务页叠加右侧滚动条。
3. 当 `LazyListState` 可以向前或向后滚动时显示滚动条；两者都不能滚动时隐藏。
4. 滚动条由浅色轨道和较深滑块组成：
   - 滑块长度反映当前可见项目数占总项目数的大致比例，并设置最小高度，避免任务很多时小到看不清。
   - 滑块位置根据首个可见项目及其滚动偏移计算，滚动列表时同步移动。
   - 滚动条只作为位置提示；用户仍在列表内容区域用手指上下拖动，不新增单独拖动滑块的交互。
5. 删除现有顶部箭头和固定长度滑块，避免把装饰误当成真实滚动位置。

## 实现范围

- 在 `YtdlApp.kt` 中给公共 `LazyColumn` 绑定当前页面独立的 `LazyListState`。
- 将 `QueueScrollIndicator` 替换为接收 `LazyListState` 的任务页动态滚动条。
- 将滚动条比例计算放进一个小型纯函数，便于覆盖边界测试。
- 不改任务排序、任务数据、下载流程、历史记录或下载页内容结构。

## 测试与验收

- 单元测试：
  - 内容不足一屏时不产生滚动条指标。
  - 内容超过一屏时滑块长度小于轨道长度。
  - 从列表顶部滚到中部和底部时，滑块位置递增并保持在轨道范围内。
- Compose 回归测试：任务较少时不显示滚动条；任务较多时显示滚动条，滚动后滑块位置发生变化。
- 前台可见模拟器验收：
  - 准备超过一屏的任务，确认右侧出现滚动条并随上下拖动移动。
  - 返回下载页，确认页面内容超过一屏时可以用手指上下拖动。
  - 确认滚动条不遮挡任务卡片、右侧状态标签或底部导航。

## 非目标

- 不给下载页增加常驻滚动条。
- 不让用户直接拖动滚动条滑块。
- 不重构页面导航或任务列表数据结构。
