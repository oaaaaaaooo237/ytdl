# Android 等待队列取消与历史删除修正计划

**Goal:** 补齐单条等待任务取消，并允许下载期间安全删除无关的 App 私有历史文件。

延续现有取消语义和 taskId 隔离规则；不改下载调度、解析器选择和媒体格式。

## Task 1：等待项取消
- [x] 增加回归测试：点击等待项取消传递该项 taskId；取消队列中间项不影响当前下载与其余顺序；已被 worker 领取时转交已有活动取消逻辑；清理失败转为可重试暂停项，不再次执行。
- [x] Coordinator 在同一锁内将目标等待项从 runnable 队列移入现有 saved 取消路径，复用持久取消与失败恢复逻辑。
- [x] Service 的带 taskId 取消命令先尝试等待项，再尝试活动项和已暂停项。
- [x] 等待卡片接入现有取消回调，提示使用“所选任务”。

## Task 2：历史删除门禁
- [x] 先测试独立私有任务文件可在另一下载存在时删除，而相关非终态任务与共享文件继续拒绝删除。
- [x] 私有输出在 Coordinator 锁保护下验证非终态 taskId 和共享引用后精确删除；外部 SAF 成品仍需空闲门禁，避免导出期间文档别名冲突。
- [x] 空输出的已中断历史可安全删除记录；不更改清缓存和取消临时目录的语义。

## Task 3：验证与交付
- [x] 顺序执行聚焦 JVM 测试、相关回归、全量 JVM 与 debug 构建。
- [x] 不通过 instrumentation 干扰用户正在进行的真实下载。主 APK 更新及可见 GUI 验证放到当前队列安全边界后执行。
- [x] 前台验证等待卡片取消、队列数量更新、被取消项不会执行、当前项正常推进和无关历史删除。

## Task 4：避免重复解析
- [x] 分析和下载固定网络配置，按 analysisKey 复用内存解析快照；按 URL 和 Cookies 摘要隔离，恢复文件不保存快照。
- [x] 用户手动双任务 480p 测试、只读监测确认两项完成。验收详见 docs/qa/android-network-queue-20261103.md。
