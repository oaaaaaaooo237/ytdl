# Android 1.0.1 Task Page and Progress Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 提供稳定的下载速度/大小展示、严格顺序执行的等待队列、取消任务重试、合并后的任务页面、清晰的历史信息、按媒体标题命名的主文件和 1.0.1 安装包。

**Architecture:** 保留现有下载管线骨架、队列卡片和历史卡片，扩展 `RuntimeDownloadState` 保存速度与阶段内固定总大小。`DownloadCoordinator` 保存当前任务和进程内等待队列快照，`DownloadService` 使用单线程执行器按 FIFO 顺序运行。新的 `tasks` 路由组合当前任务、等待任务和历史记录。历史数据库结构不变，只调整重试草稿条件与 `HistoryUiItem.meta` 的前台映射。下载管线在最终文件生成时统一采用经过文件名安全处理的媒体标题；合并中间文件继续留在应用任务目录内。

**Tech Stack:** Kotlin、Jetpack Compose、Room、JUnit/Robolectric、Chaquopy、Gradle 9.4.1、Android API 37。

- [x] **Step 2: 运行定向测试并确认 RED**

Run: `D:\DevTools\gradle-9.4.1\bin\gradle.bat :app:testDebugUnitTest --tests "com.garyapp.ytdl.download.DownloadCoordinatorTest" --tests "com.garyapp.ytdl.download.RetryHistoryPersistenceTest" --tests "com.garyapp.ytdl.ui.DownloadUiBridgeTest" --no-parallel`

- [x] **Step 3: 最小实现**

协调器维护待领取、已交给服务但尚未执行、当前执行三种状态，并向 Compose 发布等待任务快照。服务使用单线程执行器；每个启动请求只领取一条任务，任务实际开始时才从等待快照移除，结束后自动执行下一条。下载页在当前任务运行时允许把已经分析并确认的另一条地址加入队列，成功后清空本次分析输入，避免重复加入。

失败或取消终态都保存重试草稿，历史映射和操作按钮都允许取消任务“再次下载”。
