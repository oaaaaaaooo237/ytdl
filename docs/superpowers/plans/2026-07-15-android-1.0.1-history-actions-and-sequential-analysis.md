# Android 1.0.1 History Actions and Sequential Analysis Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 历史卡片操作按钮默认同排，并阻止较早地址的异步分析结果覆盖当前地址的结果。

**Architecture:** 保留现有 `HistoryCard`、`HistoryActionChip` 和分析线程，只调整操作区组合方式，并为分析请求增加进程内递增编号。地址实际变化会使旧请求失效；只有最新编号的结果允许更新 `RuntimeDownloadState`。

**Tech Stack:** Kotlin、Jetpack Compose、Robolectric Compose Test、Chaquopy、Gradle 9.4.1、Android API 37。

### Task 2: 拒绝旧地址的迟到分析结果

**Files:**
- Modify: `android/app/src/main/java/com/garyapp/ytdl/ui/YtdlApp.kt`


Run:

```powershell
D:\DevTools\gradle-9.4.1\bin\gradle.bat :app:testDebugUnitTest --tests "com.garyapp.ytdl.ui.YtdlAppDownloadFlowTest.latePreviousAnalysisCannotReplaceCurrentUrlResult" --no-parallel
```

Expected: 第一次分析的迟到结果覆盖第二次结果，或修改地址后分析按钮仍保持禁用，测试失败。

- [ ] **Step 3: 最小实现**

在 `YtdlApp` 中保存 `AtomicLong` 请求编号。每次分析取得新编号，地址实际变化时也递增编号并结束旧的“分析中”界面状态。

```kotlin
val analysisRequestRevision = remember { AtomicLong(0L) }
val requestRevision = analysisRequestRevision.incrementAndGet()

mainHandler.post {
    if (analysisRequestRevision.get() == requestRevision) {
        runtimeState = result.fold(...)
    }
}
```

Run: 与 Step 2 相同。

Expected: 第二次分析结果保持可见，第一次迟到结果被忽略。
